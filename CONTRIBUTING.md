# Contributing

Use the checksum-pinned dependencies and the [build recipe](docs/BUILDING.md).
Describe the version, behavior changes and checks performed. Distinguish a
successful cross-build from a test on actual hardware.

Preserve original notices and component licenses. Upstream modifications retain
their applicable terms. Record provenance and review the license before adding
a dependency or asset.

For a bug report, include minimal steps, the expected result and the actual
result. Review logs before attaching them: omit accounts, passwords, console
identifiers, pairing data and private network addresses. Do not attach SDKs,
third-party packages or console security-modification instructions.

Update corresponding sources and notices with each new PKG. Never replace a
published tag or release asset with different bytes; create a new version.
